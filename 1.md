# PART 1 — FIRST UNDERSTAND MONGODB

## 1. What is MongoDB?

MongoDB is a **NoSQL document database**.

Instead of storing data in traditional relational tables:

```text
Table
 ├── Row
 ├── Row
 └── Row
```

MongoDB uses:

```text
Database
   ↓
Collection
   ↓
Document
   ↓
Fields
```

For example:

```javascript
use collegeDB

db.students.insertOne({
    studentId: 1,
    name: "Arjun",
    age: 21,
    branch: "CSE"
})
```

Here:

```text
collegeDB       → Database
students        → Collection
{ ... }         → Document
studentId       → Field
1               → Value
```

# PART 7 — `$lookup`

Think of `$lookup` as approximately equivalent to a **JOIN in SQL**.

Example:

```javascript
db.students.aggregate([
    {
        $lookup: {
            from: "departments",
            localField: "deptId",
            foreignField: "deptId",
            as: "deptInfo"
        }
    }
])
```

Understand every word.

```text
from
 ↓
Which collection?

localField
 ↓
Field in current collection

foreignField
 ↓
Field in other collection

as
 ↓
Name of resulting array
```

Visualize:

```text
students
   |
   | deptId
   ↓
departments
   |
   | deptId
   ↓
deptInfo
```

# WHY DOES `$lookup` CREATE AN ARRAY?

This confuses many students.

Suppose:

```javascript
{
    studentId: 1,
    name: "Arjun",
    deptId: 101,
    deptInfo: [
        {
            deptId: 101,
            deptName: "Computer Science"
        }
    ]
}
```

`deptInfo` is an array.

That's why we frequently use:

# `$unwind`

---

# PART 8 — `$unwind`

Suppose:

```javascript
deptInfo: [
    {
        deptName: "Computer Science"
    }
]
```

After:

```javascript
{
    $unwind: "$deptInfo"
}
```

it becomes:

```javascript
deptInfo: {
    deptName: "Computer Science"
}
```

Simple way to remember:

> `$unwind` breaks an array into individual documents.

---

# PART 9 — `$project`

`$project` controls what appears in the final output.

Example:

```javascript
{
    $project: {
        _id: 0,
        studentId: 1,
        name: 1,
        department: "$deptInfo.deptName"
    }
}
```

Output:

```text
studentId | name   | department
1           Arjun    Computer Science
```

### Important syntax

```javascript
department: "$deptInfo.deptName"
```

means:

> Create a field called `department` using `deptInfo.deptName`.

# PART 10 — AGGREGATION PIPELINE

This is the central concept.

An aggregation is basically:

```text
Documents
    ↓
Stage 1
    ↓
Stage 2
    ↓

    ↓
```

Example:

```javascript

    { $match: { age: { $gte: 20 } } },
    { $sort: { age: -1 } },
    { $project: { name: 1, age: 1, _id: 0 } }
])
```

# PART 11 — SCHEMA VALIDATION

This is another major concept from Experiments 2–4.

MongoDB is schema-flexible, but we can enforce validation rules.

The basic structure:

```javascript
db.createCollection("students", {
    validator: {
        $jsonSchema: {
            bsonType: "object",

            required: [
                "studentId",
                "name",
                "age"
            ],

            properties: {
                studentId: {
                    bsonType: "int"
                },

                name: {
                    bsonType: "string"
                },

                age: {
                    bsonType: "int",
                    minimum: 18
                }
            }
        }
    }
})
```

---

Specifies the data type.


Fields that must exist.

# QUESTION 2 — TOTAL SALES PER MEDICINE

This one is **very important**.

Suppose:

```text
quantity = 5
price = 20
```

Revenue:

```text
5 × 20 = 100
```

MongoDB:

```javascript
{
    $multiply: [
        "$quantity",
        "$medInfo.price"
    ]
}
```

Complete:

```javascript
db.orders.aggregate([
    {
        $lookup: {
            from: "medicines",
            localField: "medId",
            foreignField: "medId",
            as: "medInfo"
        }
    },

    {
        $unwind: "$medInfo"
    },

    {
        $group: {
            _id: "$medInfo.medName",

            totalSold: {
                $sum: "$quantity"
            },

            totalRevenue: {
                $sum: {
                    $multiply: [
                        "$quantity",
                        "$medInfo.price"
                    ]
                }
            }
        }
    },

    {
        $sort: {
            totalRevenue: -1
        }
    }
])
```

### Understand the logic:

```text
orders
 ↓
lookup medicines
 ↓
unwind
 ↓
group by medicine
 ↓
calculate quantity
 ↓
calculate revenue
 ↓
sort
```

# What is an index?

Suppose you have 1 million patients.

You run:

```javascript
db.patients.find({
    patientId: 500000
})
```

Without an index, MongoDB may have to examine many documents.

With an index:

```text
patientId → location of document
```

MongoDB can find the required document much faster.

Think of a textbook:

### Without index

Read:

```text
Page 1
Page 2
Page 3
...
Page 500
```

### With index

Use:

```text
Index → Page 500
```

# 🚨 VIVA — LEARN THESE TODAY

Your manual itself contains 30 viva questions. BCSNS701 LAB MANUAL (1)

For your Lab Test 1, I'd especially memorize these:

### Q: What is NoSQL?

**A:** A non-relational database system.

### Q: Main advantage?

**A:** Scalability.

### Q: What is a document?

**A:** A JSON/BSON-like record containing fields and values.

### Q: What is a collection?

**A:** A group of MongoDB documents, roughly analogous to a table in an RDBMS.

### Q: What is CRUD?

**A:**

```text
Create
Read
Update
Delete
```

### Q: What is `$lookup`?

**A:** It combines documents from another collection based on matching fields, similar to a join.

### Q: What does `$unwind` do?

**A:** It deconstructs an array field into individual documents.

### Q: What does `$match` do?

**A:** Filters documents.

### Q: What does `$group` do?

**A:** Groups documents based on a specified expression and can perform calculations such as sum and average.

### Q: What does `$project` do?

**A:** Selects or reshapes fields in the output.

### Q: What does `$sort` do?

**A:** Sorts documents.

### Q: What is an index?

**A:** A data structure that improves query performance by allowing MongoDB to locate matching documents more efficiently.

### Q: What is a compound index?

**A:** An index containing multiple fields.

### Q: What is a unique index?

**A:** An index that prevents duplicate values for the indexed field/key pattern.

### Q: What is a text index?

**A:** An index used to support text search.

### Q: What is a partial index?

**A:** An index containing only documents that satisfy a specified filter condition.

### Q: Why use `explain()`?

**A:** To examine how MongoDB executes a query and evaluate performance.

### Q: What is `executionTimeMillis`?

**A:** The execution time reported for the query execution.

### Q: What is `totalDocsExamined`?

**A:** The number of documents examined during query execution.
