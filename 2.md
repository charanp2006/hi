# **Program 5 – Library Database and Indexing**

## **1. Understand the problem**

Imagine a library database. It needs to store:

- Books – information about books.
- Members – people who borrow books.
- Borrow records – which member borrowed which book and when.
- Authors – information about book authors.

MongoDB stores this information in separate collections.

**LibraryDB**

**books**

`isbn`, `title`, `authorId`, `publishedYear`, `copiesAvailable`

**members**

`memberId`, `name`, `age`, `membershipType`

**borrowRecords**

`recordId`, `memberId`, `isbn`, `borrowDate`, `returnDate`

**authors**

`authorId`, `name`, `country`

**Why four collections?**

Instead of storing all information in one huge document, we separate it into logical groups. The IDs connect related information.

For example:

- `books.authorId` refers to `authors.authorId`.
- `borrowRecords.memberId` refers to `members.memberId`.
- `borrowRecords.isbn` refers to `books.isbn`.

These are logical relationships; MongoDB does not automatically enforce foreign keys like a relational database.

## **4. Create collections with validation**

Before inserting data, we define rules that documents must follow.

### **What is schema validation?**

Suppose someone tries to insert a book with:

```
{
    isbn: 123,
    title: "MongoDB Basics",
    authorId: 1,
    publishedYear: 2020,
    copiesAvailable: -5
}
```

This is invalid because:

- ISBN should be a string, not a number.
- Available copies cannot be negative.

Schema validation prevents such invalid data from being inserted.

### **Important validation keywords**

| Keyword    | Meaning                           |
| ---------- | --------------------------------- |
| `bsonType` | Specifies the data type           |
| `required` | Fields that must be present       |
| `minimum`  | Minimum allowed value             |
| `maximum`  | Maximum allowed value             |
| `enum`     | Only specified values are allowed |

### **A. Books collection**

```
db.createCollection("books", {
    validator: {
        $jsonSchema: {
            bsonType: "object",
            required: [
                "isbn", "title", "authorId",
                "publishedYear", "copiesAvailable"
            ],
            properties: {
                isbn: { bsonType: "string" },
                title: { bsonType: "string" },
                authorId: { bsonType: "int" },
                publishedYear: {
                    bsonType: "int",
                    minimum: 1500,
                    maximum: 2025
                },
                copiesAvailable: {
                    bsonType: "int",
                    minimum: 0
                }
            }
        }
    }
})
```

Understand this:

- `db.createCollection()` creates a collection.
- `validator` defines validation rules.
- `$jsonSchema` specifies the structure.
- `bsonType: "object"` means the document must be an object.
- `required` specifies mandatory fields.
- `properties` defines rules for individual fields.

### **B. Members collection**

```
db.createCollection("members", {
```

## **6. Four types of indexes**

This is the heart of Program 5. You must know what each index does and how to create it.

### **A. Single-field index**

Creates an index on one field.

```
db.books.createIndex({ isbn: 1 })
```

- `createIndex()` creates an index.
- `isbn` is the indexed field.
- `1` means ascending order.
- `-1` means descending order.

Example query:

```
db.books.find({ isbn: "B007" })
```

**When to use:** When frequently searching books using ISBN.

### **B. Compound index**

Creates an index using two or more fields.

```
db.borrowRecords.createIndex({
    memberId: 1,
    borrowDate: -1
})
```

This index uses:

1. `memberId` in ascending order.
2. `borrowDate` in descending order.

Example query:

```
db.borrowRecords.find({
    memberId: 1
}).sort({
    borrowDate: -1
})
```

**When to use:** When searching borrowing records of a member and arranging them by date.

Important: Compound index field order matters. The index above is especially useful for queries that start with `memberId`.

### **C. Text index**

Used to search for words in text fields.

```
db.books.createIndex({ title: "text" })
```

Example:

```
db.books.find({
    $text: {
        $search: "MongoDB"
    }
})
```

This searches book titles for the keyword `MongoDB`.

**Remember:** `"text"` creates a text index. `$text` performs a text search.

### **D. Unique index**

Prevents duplicate values in a field.

```
db.members.createIndex(
    { memberId: 1 },
    { unique: true }
)
```

Suppose member ID 1 already exists. If you try to insert another member with ID 1, MongoDB rejects it.

```
db.members.insertOne({
    memberId: 1,
    name: "John",
    age: 25,
    membershipType: "Premium"
})
```



Expected behaviour

&#x20;Duplicate-key error.



**Remember:** `unique: true` prevents duplicate values in the indexed field.

### **Quick comparison**

| Index type   | Purpose            | Example                             |
| ------------ | ------------------ | ----------------------------------- |
| Single-field | One field          | `{ isbn: 1 }`                       |
| Compound     | Multiple fields    | `{ memberId: 1, borrowDate: -1 }`   |
| Text         | Word search        | `{ title: "text" }`                 |
| Unique       | Prevent duplicates | `{ memberId: 1 }, { unique: true }` |

# **Program 6 – MongoDB Sharding**

Important conceptual + practical program

## **1. First understand sharding**

Imagine a college has 10 lakh student records.

If all records are stored on one server, that server must handle all the storage and query workload.

What if we distribute the records across multiple servers?

That is called **sharding**.

Sharding is the process of distributing data across multiple servers (shards) to improve scalability and handle large amounts of data.

**Without sharding**

**One MongoDB server**

All records stored together

Single-server workload

**With sharding**

**Mongos Router**

Routes queries to appropriate shards

**Shard 1**

Part of the data

**Shard 2**

Part of the data

## **2. Important terminology**

You must understand these four terms.

| Term          | Meaning                                     |
| ------------- | ------------------------------------------- |
| Shard         | Stores a portion of the database data       |
| Mongos        | Router that directs queries to shards       |
| Config server | Stores cluster metadata and configuration   |
| Shard key     | Field used to distribute data across shards |

**Example:** Suppose you have 1 million movie documents and choose `year` as the shard key. MongoDB distributes data according to the shard-key ranges.

### **How does the query work?**

- A query containing a suitable shard-key condition can be directed to relevant shards. This is called *targeted routing*.
- A query without a useful shard-key condition may be sent to multiple shards. This is called *scatter-gather*.

## **6. Execute the performance tests**

The manual demonstrates three types of queries.

**A. Equality query**

Find movies released in 2010.

```
// Unsharded
db.movies_unsharded.find({
    year: 2010
}).explain("executionStats")

// Sharded
db.movies_sharded.find({
    year: 2010
}).explain("executionStats")
```

**B. Range query**

Find movies released between 2010 and 2014.

```
// Unsharded
db.movies_unsharded.find({
    year: {
        $gte: 2010,
        $lt: 2015
    }
}).explain("executionStats")

// Sharded
db.movies_sharded.find({
    year: {
        $gte: 2010,
        $lt: 2015
    }
}).explain("executionStats")
```

Remember:

- `$gte`: Greater than or equal to.
- `$lt`: Less than.

**C. Aggregation query**

Find average movie rating grouped by genre.

```
// Unsharded
db.movies_unsharded.aggregate([
    {
        $match: {
            year: { $gte: 2010, $lt: 2015 }
        }
    },
    {
        $group: {
            _id: "$genre",
            avgRating: { $avg: "$rating" }
        }
    }
]).explain("executionStats")
```

Run the same aggregation on the sharded collection:

```
db.movies_sharded.aggregate([
    {
        $match: {
            year: { $gte: 2010, $lt: 2015 }
        }
    },
    {
        $group: {
            _id: "$genre",
            avgRating: { $avg: "$rating" }
        }
    }
]).explain("executionStats")
```

## **Program 5 – Indexing**

**1. What is an index in MongoDB?**

An index is a data structure that improves the speed of data retrieval.

**2. What is a single-field index?**

An index created on one field of a document.

**3. What is a compound index?**

An index created on multiple fields.

**4. What is a text index?**

An index used to search text fields using keywords.

**5. What is a unique index?**

An index that prevents duplicate values in the indexed field.

**6. What does&#x20;**`1`**&#x20;and&#x20;**`-1`**&#x20;mean in an index?**

`1` means ascending order and `-1` means descending order.

**7. What is&#x20;**`explain()`**?**

It shows how MongoDB executes a query.

**8. What is&#x20;**`executionStats`**?**

It provides execution statistics such as execution time and documents examined.

**9. What is&#x20;**`totalDocsExamined`**?**

The total number of documents examined during query execution.

**10. Does indexing have disadvantages?**

Yes. Indexes consume storage and increase the overhead of write operations.

## **Program 6 – Sharding**

**1. What is sharding?**

Sharding is the process of distributing database data across multiple servers.

**2. Why is sharding used?**

To support horizontal scaling and distribute storage and workload.

**3. What is a shard?**

A server or replica set that stores a portion of the sharded data.

**4. What is Mongos?**

It is the query router in a MongoDB sharded cluster.

**5. What is a config server?**

It stores metadata and configuration information about the sharded cluster.

**6. What is a shard key?**

The field used to distribute documents across shards.

**7. What is horizontal scaling?**

Adding more servers to distribute workload.

**8. What is the difference between sharding and replication?**

Sharding distributes different portions of data across servers. Replication maintains copies of the same data across multiple servers.

**9. What does&#x20;**`sh.enableSharding()`**&#x20;do?**

It enables sharding for a database.

**10. What does&#x20;**`sh.shardCollection()`**&#x20;do?**

It converts a collection into a sharded collection using the specified shard key.
